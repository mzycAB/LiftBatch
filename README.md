# MTR 电梯批量助手 (MTR Lift Batch Helper)

一个 Minecraft Transit Railway (MTR) 4.x 的辅助模组，用于**批量设置直梯楼层编号**、**修改电梯速度**、**批量绑定/解绑楼层显示屏和外呼板**，专治高层电梯一个个手动点到崩溃的问题。

- Minecraft: **1.20.4 (Fabric)**
- 依赖: MTR >= 4.0.0（推荐 4.0.5）、Fabric API、Fabric Loader >= 0.15.0
- 模组 ID: `liftbatch`

## 六种扳手

| 扳手 | 合成（工作台） | 功能 |
| --- | --- | --- |
| 楼层批量扳手（蓝） | 铁锭×2 + 木棍（竖排） | 批量给整条电梯井的楼层编号 |
| 电梯速度扳手（紫） | 钻石×2 + 木棍（竖排） | 弹窗修改电梯速度，速度持久保存 |
| 显示屏绑定扳手（青） | 金锭×2 + 木棍（竖排） | 批量绑定楼层显示屏 |
| 外呼绑定扳手（绿） | 铜锭×2 + 木棍（竖排） | 批量绑定外呼板 |
| 显示屏解绑扳手（青+红“\”） | 红石 + 金锭 + 木棍（竖排） | 批量解除显示屏与电梯的绑定 |
| 外呼解绑扳手（绿+红“\”） | 红石 + 铜锭 + 木棍（竖排） | 批量解除外呼板与电梯的绑定 |

> 解绑扳手的外观与对应的绑定扳手相同，只是叠加了一个红色“\”标记，方便一眼区分。鼠标悬停时物品介绍会显示简短功能说明（6 字以内），详细用法见下文。

扳手也可以在创造模式物品栏的 **MTR 电梯批量助手** 分组中直接获取。

## 使用方法

### 1. 楼层批量扳手 —— 批量楼层编号

1. 手持扳手，**右键电梯井中的任意一个楼层方块**（Lift Track Floor，即用来标记楼层的轨道方块）。
2. 游戏内会弹出一个**输入窗口**：输入最下方楼层的楼层号（支持负数），例如 `-1`，然后点击**确认**按钮或直接按**回车**。
3. 模组会自动扫描该立柱（**X、Z 相同，仅 Y 不同**）上的所有楼层方块，从下到上依次编号：
   - 输入 `-1` → 楼层依次为 `-1, 1, 2, 3, ...`（**自动跳过 0 层**，符合国内楼层习惯）
   - 输入 `1` → `1, 2, 3, ...`
   - 输入 `-3` → `-3, -2, -1, 1, 2, ...`
4. 编号完成后会自动刷新 MTR 电梯数据（等效于 MTR 自带的电梯刷新器重新生成，且**保留原有电梯样式**），显示屏上的楼层名立即生效。
5. 按 **Esc** 或点击**取消**关闭窗口则不执行任何操作；输入非整数会在窗口内提示错误。楼层的描述（description）保持原样不会被改动。

### 2. 电梯速度扳手 —— 修改电梯速度

1. 手持扳手，**右键电梯井中的任意一个楼层方块**。
2. 弹出窗口显示**当前速度**，输入新速度后点**确认**或按**回车**：
   - 单位是**格/秒**：输入 `1` = 每秒 1 格，输入 `2.5` = 每秒 2.5 格
   - 原版默认速度为 10 格/秒，可输入 `10` 恢复
   - 允许范围 0.1 ~ 100
3. 确认后所有客户端的电梯动画与实际运行速度同步更新。
4. **速度保存在 MTR 的电梯数据中**（存档 `mtr` 文件夹的 JSON 里，字段 `liftbatch_speed`），重启游戏/服务器不会丢失。
5. 加速度会按比例缩放，加速/刹车的"手感"与原版一致，不会出现瞬间启停。

### 3. 显示屏绑定扳手 / 外呼绑定扳手 —— 批量绑定

两个扳手用法完全相同，只是目标方块不同：

1. 手持扳手，**先右键电梯井中的任意一个楼层方块**——这一步是"选择电梯"（聊天栏会提示已选择）。
2. **再右键该电梯任意一层的一个显示屏（或外呼板）**——模组会自动扫描该立柱上（X、Z 相同）的所有显示屏（或外呼板），按 Y 轴把每一个绑定到对应楼层的楼层方块（取该屏高度及以下最近的楼层）。
3. 绑定关系与 MTR 自带的连接器（Lift Buttons Link Connector）完全一致，只是从"一层一层点两下"变成"整列一次搞定"。
4. 选择状态保留 5 分钟，期间可以连续绑定多列（例如电梯井左右两侧各一列显示屏 + 各一列外呼板，共 4 次右键搞定）。重新右键楼层方块会切换到另一台电梯。

### 4. 显示屏解绑扳手 / 外呼解绑扳手 —— 批量解除绑定

用法与绑定扳手完全相同，效果相反：

1. **先右键电梯的楼层方块**选择要解绑的电梯。
2. **再右键要解绑的显示屏（或外呼板）列中的任意一个**——整列中所有与该电梯绑定的方块都会被解绑。
3. **只解除与所选择电梯的绑定**：如果某块外呼板同时绑定了另一台电梯（多电梯共用外呼），另一台电梯的绑定会被保留，不会误删。
4. 与原版连接器的"解除连接"模式走完全相同的代码路径，可随时用绑定扳手重新绑定。

> 提示：绑定逻辑与原版 MTR 连接器一致——显示屏会显示所绑定电梯的当前楼层与运行方向，外呼板会呼叫所绑定楼层的电梯。

## 重要特性：卸载安全

本模组**不写入任何自定义存档结构**。所有操作都直接写入 MTR 自己的数据格式：

- 楼层编号 → 楼层方块实体的 NBT（`floor_number`）
- 显示屏/外呼板绑定与解绑 → 对应方块实体的 NBT（`track_floor_pos`）
- 电梯数据刷新与速度 → MTR 存档内 `mtr` 数据（`update_data` / `generate_by_lift` 通道，与 MTR 自带工具同一条路径；速度存为电梯数据中的 `liftbatch_speed` 字段）

因此**删掉本模组后，已经设置好的楼层、已绑定/解绑的显示屏和外呼板全部保持原样**，电梯照常运行。卸载模组后唯一的变化是：自定义过的电梯速度会回到原版 10 格/秒（`liftbatch_speed` 字段残留在数据中但会被 MTR 忽略，无任何副作用；重新安装本模组后速度恢复生效）。

## 使用建议与注意事项

- 适用于**直上直下的标准电梯井**（所有楼层方块在同一 X、Z 立柱上）。如果电梯轨道是弯曲的（楼层不在同一立柱），楼层批量扳手只会处理当前立柱的楼层。
- 先用楼层批量扳手（或 MTR 电梯刷新器）完成楼层编号后，再做显示屏/外呼板绑定，可以确保绑定消息里的楼层号准确。
- 若右键已解锁的外呼板下半部分没反应，请点击外呼板**上半部分**，或按住 **Shift 右键**（Shift 右键总是优先交给扳手处理）。
- 扳手对与电梯无关的方块右键不会拦截，不影响正常游戏。

## 从源码构建

```bash
# 需要 JDK 17+（推荐 21），Gradle 8.6+
gradle build
```

产物位于 `build/libs/liftbatch-1.2.2.jar`。MTR 4.0.5 以本地 Maven 仓库形式放在 `libs/` 目录下，构建无需访问 Modrinth。

## 技术实现简介

- 通过 Fabric API 的 `UseBlockCallback` 在方块交互最前端拦截扳手点击（因此不会被 MTR 方块自身的交互逻辑抢占，例如外呼板的呼梯判定）。
- 楼层号/速度输入通过游戏内弹窗完成：服务端右键时经自定义包通知客户端打开输入窗口（文本框 + 确认/取消按钮，回车即确认），确认后回传或走 MTR 更新通道，服务端校验（方块类型 + 32 格距离）后执行。
- **速度实现**：通过两个 Mixin 注入 MTR 电梯模拟核心——
  - `LiftSchema` 序列化钩子：给电梯数据增加 `liftbatch_speed` 字段（存格/秒），随 MTR 的存档周期自动保存/读取；
  - `Lift.tick` 物理钩子：`@ModifyConstant` 按比例缩放原版加速度常量（4.0E-6），`@Redirect` 接管速度上限的 `Utilities.clamp` 调用（原版 ±0.01 格/毫秒 = 10 格/秒），未设置速度时完全不改变原版行为；
  - 速度修改经 MTR 自己的更新通道（`PacketUpdateData` + `UpdateDataRequest.addLift`，与电梯自定义界面同一条路径）下发到服务器模拟器并同步所有客户端。
- 扫描逻辑：以点击位置为基准，沿整条 Y 轴立柱扫描（X、Z 不变），收集 MTR 对应方块；解绑时只移除指向所选电梯楼层方块的绑定记录。
- 电梯数据刷新：调用 MTR 的 `Init.sendMessageC2S("generate_by_lift", ...)`，与 MTR 自带电梯刷新器走完全相同的路径（`GenerateByLift`），已有电梯的样式与尺寸会被保留，仅替换楼层列表。
